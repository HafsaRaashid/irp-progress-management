# Plan — The Student Surface Refresh

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the student surfaces warmer and more legible without touching the status vocabulary, the accessibility floor, or the mentor's view — and close `docs/design-system.md` §13's "Bistec brand colour" open item with a value sampled from the real asset.

**Architecture:** One colour swap (four tokens, hue 253.4° sampled from `hearts-academy-mark.png`), protected by a **new 60-pair WCAG gate that parses `globals.css` itself** rather than a hand-maintained copy of it. Expressive behaviour reaches student surfaces as **opt-in props defaulted off**, named after what they do and never after who uses them, so the mentor frame is unchanged and the later mentor redesign turns them on rather than unpicking them. The student side goes from two routes to two routes — `/` keeps the composer, `/my-month` becomes `/my-progress` and absorbs the feedback band.

**Tech Stack:** Next.js 16 App Router (Server Components, Server Actions, `typedRoutes`), Tailwind CSS 4 with CSS custom properties, Vitest + Testing Library, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-05-student-surface-refresh-design.md` — all sections.

**Branch:** `feat/ui-ux-improvements` — already created. One branch, one PR, merged before the next plan starts.

**FRs:** FR-29 (student dashboard) and FR-30 (no score, rank, leaderboard, or peer data — must not weaken). The brand colour closes a design-system open item rather than serving an FR, on the same footing as O-15's frame work.

## Global Constraints

Every task's requirements implicitly include this section.

- **No `apps/api` change, no `spec/openapi.yaml` change, no Prisma migration.** The streak is derived from data `getMyDashboard` already returns. If a task appears to need an API field, stop — it is out of scope and the design is wrong.
- **One new route, by rename only.** `/my-month` → `/my-progress` in Task 9. No other route is added.
- **No hand-written `fetch` in `apps/web`.** Import from `@irp/client` only. Server Actions are not `fetch` and are the established pattern.
- **`pnpm typecheck` is not sufficient for `apps/web`.** `AUTH_DEV_BYPASS=false pnpm --filter @irp/web build` is part of the required verification set for **every** task here — all of them touch `apps/web`.
- **`pnpm --filter @irp/web build` needs `AUTH_DEV_BYPASS=false`** explicitly. `.env.local` sets it true, `next build` forces `NODE_ENV=production`, and `assertBypassNotInProduction` then correctly refuses. That is guard one working — never weaken it.
- **A `Route` assignability error is stale-cache first, real second. Rebuild before believing `TS2322: Type '"/my-progress"' is not assignable to type 'Route'`, and never fix one by casting or by widening a `Link` href type.**

  **The mechanism, measured on 2026-10-05 against Next 16.2.12 — `CLAUDE.md`'s description of it is stale and this supersedes it.** `apps/web/next-env.d.ts` is **regenerated by whichever Next command ran last**, and its third line is an `import` naming the route union `tsc` will read:

  | Last command | `next-env.d.ts` imports |
  |---|---|
  | `next build` | `./.next/types/routes.d.ts` |
  | `next dev` | `./.next/dev/types/routes.d.ts` |

  So the dev copy is **not** "a file `tsconfig` never reads" — after any `next dev`, it is precisely what `tsc` reads. Both trees are git-ignored and nothing invalidates either.

  This makes the hazard worse than documented, in a way that bit this plan's own baseline: a `next dev` killed mid-write leaves `.next/dev/types/routes.d.ts` **truncated**, and `pnpm typecheck` then fails with `TS1128: Declaration or statement expected` pointing into a generated file — no route involved, nothing wrong with the source. The remedy is the same either way: run `AUTH_DEV_BYPASS=false pnpm --filter @irp/web build`, which rewrites `next-env.d.ts` back to the build tree and regenerates it.
- **Do not substitute token values.** Copy every hex verbatim from this plan; never retype one from memory. The gate in Task 2 is what catches a typo, but only after it exists.
- **Every colour resolves through a token.** No literal hex and no Tailwind colour utility (`bg-white`, `text-slate-500`, …) anywhere in `apps/web`. This is convention, not a gate — nothing will catch a violation for you.
- **Status is never colour alone** (design-system §12). `StatusPill` and `CountsRow` are **not modified by any task in this plan.** The four status colours are not modified either.
- **FR-30 is structural, not cosmetic.** Nothing added here may render a score, a rank, a percentile, a peer, or any figure that invites comparison. The streak is a count of the student's own days with its own denominator — never a rate, never a grade.
- **The mentor view must come out byte-for-byte unchanged.** Every new component capability is opt-in and defaults off. Task 10 verifies this by inspection of the mentor surfaces, not by assumption.
- **Desktop only, min 1280px** (NFR-13). No responsive or mobile treatment, in any task.
- **Playwright: `workers: 1` and `retries: 0` stay pinned**, and `chromium-dark` stays scoped by `testMatch` to `dark-theme.spec.ts` alone. `fullyParallel: false` orders tests *within* a file only — it is not "run serially". Never widen either.
- **`expect: { timeout: 20_000 }` in `playwright.config.ts` stays.** It budgets for two cold Turbopack compiles inside the first assertion. Do not "tidy" it down.
- **Prove every new gate red before trusting it.** A gate never seen to fail is not a gate. Tasks 2 and 3 both carry an explicit red step, and a task that skips it is not complete.
- **Conventional commits**, one per task. ADRs land in Task 1, before the code they govern.
- **`// ASSUMPTION: O-n` in code** wherever an open point is being assumed past. O-7 applies to the streak (Task 7).

### Task 2: The contrast gate

**This task lands before any colour changes, deliberately.** It must be green on *today's* palette and red on a broken one before the swap, or it proves nothing about the change it exists to verify. The design system claims "35 pairs across both themes pass"; nothing in the repository computes luminance.

**Files:**
- Modify: `apps/web/test/theme-tokens.test.ts`

**Interfaces:**
- Consumes: the token declarations in `apps/web/app/globals.css`, parsed at test time.
- Produces: a gate Tasks 3 and 6 must keep green.

- [ ] **Step 1: Write the failing test**

Append to `apps/web/test/theme-tokens.test.ts`. The file is already `// @vitest-environment node` and already imports `readFileSync` and `path` — reuse them, do not re-import.

Two design points that are load-bearing:

1. **The tokens are parsed out of the stylesheet, never retyped.** A hard-coded second list is one more thing to drift, and would verify the test against itself.
2. **The dark set is the light set with the dark block applied over it**, which is exactly how the cascade works. That is what keeps `--brand-card` correctly white in dark, and it means a token that *should* have a dark value but does not will be measured at its light value — which is the bug, surfaced.

```ts
/**
 * The contrast gate. design-system §3 claims "35 pairs across both themes pass
 * WCAG AA" and "do not substitute values" — and until this existed, nothing
 * checked it. The duplication test above catches the two dark blocks drifting
 * FROM EACH OTHER; it cannot catch both being wrong together. Edit a colour
 * consistently in both places and every other test in this file stays green.
 *
 * Pairs are derived from what the code ACTUALLY renders, not from §3's prose,
 * so a pair here can always be traced to a call site. Two pairs currently sit
 * at ~101% of their floor (--st-absent on --surface, 4.55:1; --line-strong on
 * --surface in dark, 3.03:1) — they are why this is worth having.
 */
describe("WCAG contrast", () => {
  const css = readFileSync(
    path.join(import.meta.dirname, "..", "app", "globals.css"),
    "utf8",
  );

  function tokensIn(block: string): Record<string, string> {
    const out: Record<string, string> = {};
    for (const m of block.matchAll(/--([a-z-]+):\s*(#[0-9a-f]{6})\s*;/gi)) {
      out[m[1]!.toLowerCase()] = m[2]!.toLowerCase();
    }
    return out;
  }

  // The FIRST :root block is the light base. The dark block overrides a subset
  // of it — so dark is light-with-overrides, which is what the cascade does and
  // is why --brand-card stays white in dark without a dark entry.
  const lightBlock = /:root\s*\{([\s\S]*?)\n\}/.exec(css)?.[1];
  const darkBlock = /\/\* dark-tokens:start \*\/([\s\S]*?)\/\* dark-tokens:end \*\//.exec(css)?.[1];

  it("parses both token sets out of the stylesheet", () => {
    expect(lightBlock).toBeDefined();
    expect(darkBlock).toBeDefined();
  });

  const light = tokensIn(lightBlock ?? "");
  const dark = { ...light, ...tokensIn(darkBlock ?? "") };

  /** WCAG 2.x relative luminance, sRGB. */
  function luminance(hex: string): number {
    const [r, g, b] = [1, 3, 5].map((i) => {
      const c = parseInt(hex.slice(i, i + 2), 16) / 255;
      return c <= 0.04045 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4;
    }) as [number, number, number];
    return 0.2126 * r + 0.7152 * g + 0.0722 * b;
  }

  function ratio(a: string, b: string): number {
    const [hi, lo] = [luminance(a), luminance(b)].sort((x, y) => y - x) as [number, number];
    return (hi + 0.05) / (lo + 0.05);
  }

  /** [foreground, background, floor, the call site it comes from] */
  // NOTE: not ReadonlyArray<T>. @typescript-eslint/array-type ships in
  // stylisticTypeChecked, which eslint.config.mjs enables repo-wide, and it
  // forbids that form. This is ESLint own autofix output.
  const PAIRS: readonly (readonly [string, string, number, string])[] = [
    // Body text — §12's 4.5:1 floor.
    ["ink", "bg", 4.5, "body copy on the canvas"],
    ["ink", "surface", 4.5, "copy inside a Panel"],
    ["ink", "surface-sunk", 4.5, "copy in the dense zone"],
    ["ink", "primary-weak", 4.5, "copy on a primary-tinted fill"],
    ["ink-muted", "bg", 4.5, "labels, hints, placeholders"],
    ["ink-muted", "surface", 4.5, "SectionLabel inside a Panel"],
    ["ink-muted", "surface-sunk", 4.5, "muted copy in the dense zone"],
    // --primary is TEXT in four places — this is why it carries 4.5, not 3.
    ["primary", "bg", 4.5, ".text-link:hover on the canvas"],
    ["primary", "surface", 4.5, "StatusPill's --st-review inside a Panel"],
    ["primary", "primary-weak", 4.5, ".nav-item[data-active], .chip[aria-current]"],
    ["surface", "primary", 4.5, ".btn-primary label on its own fill"],
    // The status vocabulary, on every surface it is drawn on.
    ["st-ok", "bg", 4.5, "on-time count"],
    ["st-ok", "surface", 4.5, "on-time pill in a Panel"],
    ["st-ok", "surface-sunk", 4.5, "on-time in the dense zone"],
    ["st-late", "bg", 4.5, "late count"],
    ["st-late", "surface", 4.5, "late pill in a Panel"],
    ["st-late", "surface-sunk", 4.5, "late in the dense zone"],
    ["st-absent", "bg", 4.5, "absent count"],
    ["st-absent", "surface", 4.5, "absent pill in a Panel"],
    ["st-absent", "surface-sunk", 4.5, "absent in the dense zone"],
    ["st-missed", "bg", 4.5, "missed count"],
    ["st-missed", "surface", 4.5, "missed pill, role=alert copy"],
    ["st-missed", "surface-sunk", 4.5, "missed in the dense zone"],
    ["st-missed", "primary-weak", 4.5, "error copy on a tinted fill"],
    // Non-text UI boundaries — WCAG 1.4.11, 3:1. primary/bg and primary/surface
    // repeat above at a lower floor on purpose: they document a separate
    // requirement (focus ring, today ring) that survives if the text use goes.
    ["line-strong", "bg", 3, ".control borders on the canvas"],
    ["line-strong", "surface", 3, ".control borders inside a Panel"],
    ["line-strong", "surface-sunk", 3, ".control borders in the dense zone"],
    ["primary", "bg", 3, ":focus-visible ring"],
    ["primary", "surface", 3, "the ribbon's today ring"],
    ["st-missed", "surface", 3, ".btn-danger border"],
  ];

  it("covers 30 pairs per theme", () => {
    expect(PAIRS).toHaveLength(30);
  });

  for (const [themeName, tokens] of [["light", light], ["dark", dark]] as const) {
    describe(themeName, () => {
      for (const [fg, bg, floor, where] of PAIRS) {
        it(`--${fg} on --${bg} meets ${String(floor)}:1 (${where})`, () => {
          const f = tokens[fg];
          const b = tokens[bg];
          // A missing token is a failure, not a skip — otherwise a renamed
          // token silently removes its own coverage.
          expect(f, `--${fg} not found in the ${themeName} tokens`).toBeDefined();
          expect(b, `--${bg} not found in the ${themeName} tokens`).toBeDefined();
          expect(ratio(f!, b!)).toBeGreaterThanOrEqual(floor);
        });
      }
    });
  }
});
```
